### Полная фиксация сессии 2026-10-10

**Что и зачем.** В `core/preference/api` и `core/preference/impl` добавлены `SenderAvatarSettings`, агрегирующий manager и тест всех восьми сочетаний прежних параметров. В `legacy/ui/legacy/src/main/res/xml/general_settings.xml` три действующих переключателя собраны в отдельном экране без смены ключей. В каталоге feature flags добавлен `enable_sender_avatar_settings` со значением `false` по умолчанию. Цель — собрать старые настройки в одном месте, не потерять выбор пользователя при обновлении и подготовить безопасное включение будущего resolver.

**Как работает и как отключить.** Агрегирующий manager читает и сохраняет прежние настройки списка и уведомлений через существующие managers. Экран использует прежние ключи, поэтому отдельная миграция этих трёх значений не нужна. Новый флаг пока не скрывает старые рабочие настройки; в будущем он должен выключать только новый resolver и сетевые логотипы, возвращая контакт/монограмму. BIMI, общий resolver и щит ещё не реализованы. Щит запрещён без результата проверки, привязанного к конкретному письму.

**Сборка и инфраструктура.** В `C:\Projects\Mail\.tools` вне Git установлены Temurin JDK 21 и Android SDK. Локальный `local.properties` игнорируется Git. Полная проверочная `:app-thunderbird:assembleDebug` собрала `fossDebug` и `fullDebug`, после чего принято [D-006](decisions.md): дальше собирать только `full` через `:app-thunderbird:assembleFullDebug`. В `distrib/` оставлен только `thunderbird-full-debug.apk`. Это debug APK для тестов, не коммерческий release.

**Проверка.** Успешны `:core:featureflag:jvmTest`, `:core:preference:api:jvmTest`, `:core:preference:impl:jvmTest`, профильные `spotlessCheck`, `:legacy:ui:legacy:assembleDebug` и `:app-thunderbird:assembleDebug` (`BUILD SUCCESSFUL`, 2248 задач, 29 минут 38 секунд). Сгенерированный ключ `ENABLE_SENDER_AVATAR_SETTINGS` и packaged JSON проверены поиском. `git diff --check` успешен. Установка и обновление поверх старого APK не проверены: устройство или эмулятор не подключён.

**Незавершённое.** В [implementation-plan.md](sender-avatars/implementation-plan.md) подтверждены задачи: единый `SenderAvatarResolver`, запрет щита без проверки конкретного письма, телефонное обновление старой установки и добавление `showContactPictureInNotification` в резервную копию. Поиск подтвердил отсутствие resolver/verification-контракта и отсутствие ключа уведомлений в `GeneralSettingsDescriptions.SETTINGS`.

**История Git и выпуск.** Commit hash и PR отсутствуют; рабочее дерево не закоммичено. Push не выполнен, потому что `origin` указывает на официальный upstream и URL репозитория владельца отсутствует. Deploy и Docker не выполнялись: для Android-приложения серверный компонент не определён. Пользовательское «Обновление системы» не опубликовано, потому что функция не прошла телефонную приёмку и не выпущена.

**Проверка памяти.** `scripts/project/tests/Test-Memory.ps1` прошёл: 15 тестов, 0 ошибок. `scripts/project/Check-Memory.ps1` завершился с кодом 1 из-за 25 ранее существовавших проблем незавершённой `.memory-bank/code-map`: шесть файлов не зарегистрированы в картах и в них есть ссылки на отсутствующие документы/каталоги. Новые или изменённые в этой сессии записи в списке ошибок отсутствуют. Исправление `code-map` вынесено за границы этой фиксации, чтобы не создавать отсутствующие документы без отдельного решения владельца.

## 2026-10-15: Подключение resolver и безопасная загрузка BIMI

**Что и зачем.** Общий `SenderAvatarResolver` подключён ко всем найденным путям показа аватара отправителя: трём вариантам списка, заголовку открытого письма, участникам From/Sender и одиночным уведомлениям. Это устраняет разные правила выбора изображения. Везде используется точная ссылка аккаунт/папка/UID; To/Cc/Bcc/Reply-To намеренно остаются контактами без брендового подтверждения.

**Безопасность.** Создан отдельный BIMI API и реализация DNS/HTTPS-загрузки. Реализация блокирует внутренние адреса, нестандартный порт, небезопасные перенаправления, большой или неверный ответ и активное содержимое SVG; дисковый кэш имеет срок и лимит. Щит выдаётся только при доказательстве конкретного письма. BIMI пока не подключён к Android UI: нет доверенного DMARC-источника и SVG-растеризации, поэтому сетевой логотип пользователю не показывается.

**Проверка.** Четыре независимых агента проверили соответственно уведомления, все варианты списка, открытое письмо и BIMI. После их замечаний исправлены публичность типа результата, сигнатура preview и Android-среда новых тестов. Успешны компиляция `legacy:ui:legacy`, профильные тесты списка/письма/участников/уведомлений, 24 теста BIMI, `git diff --check` и полный `spotlessCheck`. Телефонная проверка не выполнялась.

**Откат и остаток.** Новый путь отключается флагом `enable_sender_avatar_settings` без удаления сохранённых ключей. Дальше нужны DMARC-адаптер, SVG-растеризация, подключение BIMI к resolver/UI, проверка обновления старого APK и все сценарии на телефоне.

**Финальная сборка 2026-10-16.** `:app-thunderbird:assembleFullDebug` завершился успешно за 10 минут 53 секунды: 2189 задач. В `distrib/thunderbird-full-debug.apk` помещён файл размером 48 413 235 байт, SHA-256 `959D4256EEF6E96F3972B72BC43A54E31C0621FF59EF94DFA741EEF50BC8F658`. `apksigner` подтвердил схемы v1/v2 и сертификат `Android Debug`. APK пригоден для тестов, но не для коммерческой публикации.
