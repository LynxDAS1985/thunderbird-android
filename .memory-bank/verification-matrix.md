# Матрица обязательных проверок

Матрица выбирает проверки по изменённому поведению и файлам. Она дополняет
[AGENTS.md](../AGENTS.md), а не отменяет его требования. Команды выполняются из
`C:\Projects\Mail\thunderbird-android`. Проверки разных строк складываются;
наличие документации в diff не превращает смешанную задачу в «только docs».

## Сравнение подходов и десять идей

До создания матрицы сверены все 15 файлов памяти, правила, CI и применимые docs.
Общий запуск Android для любого текста создаёт нерелевантную зависимость от SDK.
Одной проверки ссылок недостаточно для форматирования docs и тем более кода.
Выбран набор проверок по области изменения с отдельным учётом блокировок.

| № | Идея и решение | Польза; последствие отказа; трудность |
|---|---|---|
| 1 | Внедрено: пять строк матрицы | Видна обязательная проверка для каждого изменения; без неё легко пропустить тест; нужно классифицировать смешанный diff |
| 2 | Внедрено: источник каждой команды | Можно сверить команду с CI; без источника команды устаревают; нужны повторные сверки после обновления upstream |
| 3 | Внедрено: отдельные статусы проверки и окружения | Отсутствие SDK не маскирует ошибку ссылки; без разделения получается ложная блокировка или ложный успех; требуется точный вывод команды |
| 4 | Внедрено: приоритет багфикса | Сохраняет тест воспроизведения и полный минимум AGENTS; без него узкие проверки обходят регламент; нужен прогон до и после исправления |
| 5 | Внедрено: три контрольных сценария | Проверяет границы применения матрицы; без них документ остаётся декларацией; сценарии не заменяют реальные Android-тесты |
| 6 | Автоматический контроль памяти: интеграция команд других исполнителей | Ловит ссылки и пропуски карт; без него нужен ручной контроль; дождаться реализации и проверить её интерфейс |
| 7 | Диагностика окружения: интеграция команд других исполнителей | Показывает конкретный отсутствующий компонент; без неё причины приходится искать вручную; диагностика не доказывает успешную сборку |
| 8 | Отдельный журнал доказательств: не создавать дубль | Уже есть [work-log.md](work-log.md); второй журнал расходится с первым; ответственному за интеграцию надо перенести итог туда |
| 9 | Новый регламент выпуска: не создавать дубль | Уже есть [deployment.md](deployment.md) и [branding.md](branding.md); копия быстро устареет; здесь оставить только критерии проверок |
| 10 | Пять независимых проверяющих: задания подготовлены, запуск не подтверждён | Независимая проверка может найти пропуски; без неё остаётся самопроверка; нужны реальные агенты с результатами, инструмент их запуска здесь недоступен |

Команды уже собраны в [testing.md](testing.md), процесс в [workflow.md](workflow.md).
Новое содержание здесь: выбор обязательных проверок, их границы и доказательства.

## Выбор обязательных проверок

Перед выбором проверить `git status --short --untracked-files=all`,
`git diff --name-only` и `git diff --cached --name-only`. Просмотреть содержимое
изменений, включая новые файлы. Изменение CI, Gradle, ресурсов, manifest или
генератора кода не относится к «только docs». Удаления и переименования тоже
требуют проверки входящих ссылок и потребителей.

| Область | Обязательный набор | Критерий и ограничение |
|---|---|---|
| Только память / docs | M1, M2, обязательный D1; для Markdown CI также D2; для изменения книги `docs/` D3 | Файлы непустые, относительные ссылки и изменённые якоря корректны, новые страницы зарегистрированы в соответствующих картах, формат проверен. Ограниченный охват Flexmark не отменяет обязательный D1. Android-тесты не подтверждаются и не требуются для проверки самого текста |
| PowerShell-инструменты | M2, тесты изменённого инструмента: M3 для памяти, E2 для окружения; M1 при изменении памяти; E1 для проверки реальной диагностики окружения | Проверить позитивный и негативный случаи, код выхода и отсутствие побочных изменений. Нет скрипта или теста: проверка не выполнена. Для исправления ошибки дополнительно строка «Багфикс» |
| Android-логика, ресурсы, сборка | E1; узкие существующие задачи тестов, lint, detekt, spotlessCheck затронутых модулей; сборка затронутого приложения. A1 как общий набор, A2 для целевого приложения | Нужны успешные задачи и отчёты поведения. Для общей логики учитывать оба приложения. При изменении архитектурных границ или зависимостей дополнительно A4; инструментальные сценарии требуют A3. Нет SDK: соответствующие Android-проверки заблокированы |
| Багфикс | Добавить или обновить регрессионный тест; получить падение до исправления, когда применимо; после исправления выполнить A1 и все относящиеся к ошибке проверки | Минимум AGENTS: `test lint detekt spotlessCheck`. Узкий тест, PS-тесты или `testsOnCi` этот минимум не заменяют. Строка имеет приоритет независимо от расширения файла. Неприменимость падения до исправления нужно обосновать, а не молча пропустить |
| Бренд / выпуск | Для плана в Markdown применима строка docs. Для ресурсов, applicationId, OAuth или APK: Android-набор, A2, проверки badging нужных вариантов из CI, проверка установки, обновления и входа; для выпуска полный релизный чек-лист | Имя, иконки, идентификатор, подпись и версия проверены на конкретном артефакте; обновление сохраняет данные; вход работает с собственным OAuth. Записаны SHA-256, вариант, устройство и результат. Debug APK не доказывает готовность подписанного release |

Для багфикса в документации или PS матрица не вводит исключение из буквального
требования AGENTS. При невозможности выполнить A1 остаётся явная блокировка этого
минимума. Добавление матрицы как документа процесса само по себе не является
исправлением поведения Android или PS-инструмента. Нельзя переименовать реальный
багфикс в документационную задачу ради сокращения проверок.

## Команды и источники

Каждую команду запускать отдельно и сразу фиксировать её код выхода и результат.
Для Windows ниже используется `gradlew.bat`, в CI те же задачи вызываются через
`./gradlew`. Не запускать несколько Gradle-сборок рабочего каталога одновременно.

| ID | Команда из корня | Источник / граница |
|---|---|---|
| M1 | `powershell -NoProfile -File scripts/project/Check-Memory.ps1` | Инструмент других исполнителей; перед использованием прочитать фактический файл и справку |
| M2 | `git diff --check` и `git diff --cached --check` | Проверяют отслеживаемые изменения; новые файлы дополнительно проверить на пробелы в конце строк и завершающий перевод строки |
| M3 | `powershell -NoProfile -File scripts/project/tests/Test-Memory.ps1` | Тесты инструмента памяти; не Android-тесты |
| E1 | `powershell -NoProfile -File scripts/project/Test-Environment.ps1` | Диагностика окружения; не запуск тестов приложения |
| E2 | `powershell -NoProfile -File scripts/project/tests/Test-Environment.Tests.ps1` | Тесты диагностики, включая сценарии отсутствующих компонентов |
| D1 | `.\gradlew.bat spotlessFlexmarkCheck` | [quality-markdown.yml](../.github/workflows/quality-markdown.yml) |
| D2 | `mdbook test docs` | Тот же Markdown CI; не полная проверка всех ссылок |
| D3 | `mdbook build docs` | [HOW-TO-DOCUMENT.md](../docs/HOW-TO-DOCUMENT.md), [build-docs.yml](../.github/workflows/build-docs.yml) |
| A1 | `.\gradlew.bat test lint detekt spotlessCheck` | Обязательный минимум багфикса в AGENTS |
| A2 | `.\gradlew.bat :app-thunderbird:assembleDebug` | AGENTS и [development-environment.md](../docs/contributing/development-environment.md); для второго затронутого приложения также `.\gradlew.bat :app-k9mail:assembleDebug` |
| A3 | `.\gradlew.bat connectedAndroidTest` | AGENTS и [testing-guide.md](../docs/contributing/testing-guide.md); нужны устройство или эмулятор |
| A4 | `.\gradlew.bat dependencyGuard :quality:konsist:test` | [quality-checks.yml](../.github/workflows/quality-checks.yml); не отменяет остальные проверки CI |
| A5 | `.\gradlew.bat testsOnCi --parallel` | [build-android.yml](../.github/workflows/build-android.yml); набор CI, не синоним A1 |

На момент первоначальной сверки 2026-10-09 каталога `scripts/project/` ещё не было.
M1, M3, E1, E2 являются точками интеграции, а не заявлениями о готовых инструментах.
Если файлы появились, сначала проверить их параметры и способ запуска тестов;
не выдумывать флаги, не устанавливать новые зависимости ради этой матрицы.
Проверка E1 может сообщить об отсутствии SDK: это ожидаемый результат диагностики,
а не доказательство ошибки самого инструмента. Его корректность подтверждает E2.

## Почему SDK не блокирует любую документацию

В `build-android.yml` и `quality-checks.yml` фильтр `pull_request.paths-ignore`
исключает `**.md`. Это аргумент для разделения областей, а не обещание, что CI
никогда не запустит Android: push в `main` имеет другие условия, а смешанный PR
не исключается. Markdown CI по-прежнему запускает D1 и D2.

В [SpotlessPlugin.kt](../build-plugin/plugin/src/main/kotlin/net/thunderbird/gradle/plugin/quality/spotless/SpotlessPlugin.kt)
корневой Flexmark проверяет `*.md`, `docs/*.md`, `docs/**/*.md`.
Отдельного target для `.memory-bank/` нет. Успешный D1 не подтверждает проверку
ссылок или форматирования всей памяти. Книга mdbook также не включает память.

M1 и ручная проверка ссылок/структуры не требуют Android SDK. Отсутствие SDK
не мешает выполнить их и записать результат. D1 использует Gradle и может
остановиться при конфигурации проекта из-за JDK, SDK или загрузки зависимостей.
В таком случае статус именно D1: «заблокировано», с точной причиной, без замены
успехом M1. Нельзя объявлять весь набор docs успешным, пока обязательный D1 или
D2 не выполнен. Для изменения только памяти Android-набор неприменим; для
Android-изменения отсутствие окружения оставляет Android-проверки обязательными.

## Форма доказательства

Текущая граница завершения, подтверждённая пользователем: `scoped local checks PASS`
при успешных проверках назначенного документа; полный CI: `BLOCKED`.
Родитель подтвердил попытку `spotlessFlexmarkCheck`: остановка из-за Java до
выполнения задач. Это переданное подтверждение, не собственный повторный запуск;
код выхода здесь не предоставлен. Обязательный D1 не пройден. Локальный успех
не разрешает обход Markdown Gradle проверки ради коммита. Commit/push не выполняются.

Для каждой применимой проверки записать: список файлов, ID проверки, точную
команду, дату, код выхода, существенный вывод и путь к отчёту, если он создан.
Статусы: «пройдено», «ошибка», «заблокировано», «не запускалось», «неприменимо».
Для двух последних нужна причина. Не приравнивать отсутствие запуска к успеху.
Проценты ускорения и экономию времени без измерений не указывать.

Новая память должна быть зарегистрирована в `CLAUDE.md` и `.memory-bank/README.md`.
В этой подзадаче разрешён только данный файл; регистрацию выполняет ответственный
за общие карты. До регистрации интеграционная проверка M1 может обоснованно падать.
Это проблема регистрации, а не Android SDK. Общие журналы здесь не изменяются.

## Три контрольных сценария

| Сценарий | Воспроизводимая проверка | Ожидаемый вывод матрицы |
|---|---|---|
| Документация | Изменён только данный файл; проверить его непустоту, локальные ссылки, пробелы и перевод строки; отдельно проверить регистрацию в картах | Структуру можно проверить без SDK. Нерегистрированный файл блокирует интеграцию памяти. Android-тесты неприменимы; CI D1/D2 учитываются отдельно |
| Сломанная ссылка | В памяти процесса проверить путь `.memory-bank/__verification_missing__.md` через `Test-Path -LiteralPath`; затем существующий `.memory-bank/testing.md` | Первый результат `False`, второй `True`: дефект ссылки блокирует docs независимо от SDK. Не создавать сломанную ссылку в общих документах |
| Android-изменение | Рассмотреть изменение `app-thunderbird/build.gradle.kts` вместе с этим Markdown; проверить наличие реального файла и Android-задач в CI | Это смешанный набор: обязательны Android-проверки и проверки docs. Отсутствие JDK/SDK блокирует Android, успешные ссылки его не заменяют. При багфиксе дополнительно полный A1 |

Это контроль применимости матрицы, а не тест поведения приложения. Проверка
`Test-Path` во втором сценарии проверяет существование цели; она не является
тестом ещё не готового M1. После появления M3 нужны его настоящие негативные
тесты сломанных ссылок. Результаты текущего прогона приведены ниже.

## Пять независимых проверок для интегратора

Каждому дополнительному агенту назначить чтение без правок общих файлов и получить
отдельный отчёт с командами, фактическим выводом и ограничениями:

1. Сверить выбор docs/Android с фильтрами CI и target Flexmark.
2. Проверить M1/M3 на корректной памяти и сломанной ссылке после готовности скриптов.
3. Проверить E1/E2 и различение отсутствующего SDK и ошибки диагностики.
4. Проверить все положения AGENTS о багфиксах, включая падение до исправления.
5. Проверить бренд/выпуск по [ADR-0006](../docs/engineering/adr/0006-white-label-architecture.md), [релизному чек-листу](../docs/release/testing-checklist.md) и [чек-листу разработчика](../docs/release/developer-checklist.md).

В текущей сессии дополнительные агенты не запущены: доступного инструмента
делегирования нет. Эти задания не считаются независимым подтверждением пользы.
