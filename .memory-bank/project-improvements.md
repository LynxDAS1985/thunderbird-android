# Улучшения ведения проекта

Дата оценки: 2026-10-09. Задача: предложить 10 вариантов и внедрить лучшие 5 после проверки пятью дополнительными агентами.
Выбор основан на текущих проблемах: ручная проверка памяти, недоступная Java, неопределённые границы проверок и неподготовленный выпуск.

## Десять вариантов

| ID | Улучшение | Польза и последствие отказа | Цена и риск внедрения | Решение |
|---|---|---|---|---|
| I-01 | Автоматическая проверка памяти | Находит потерянные ссылки и незарегистрированные документы; без неё легко пропустить ошибку | Нужно поддерживать ограниченный формат ссылок и тесты | Внедрить |
| I-02 | Проверка окружения перед сборкой | Сразу показывает отсутствующие инструменты; без неё причина сбоя выясняется внутри Gradle | Диагностика не заменяет сборку и не гарантирует исправность SDK | Внедрить |
| I-03 | Матрица проверок по типу изменения | Объясняет, какие проверки обязательны; без неё можно проверить лишнее или пропустить важное | Матрицу нужно обновлять вместе с CI | Внедрить |
| I-04 | Карточка задачи и передачи работы | Сохраняет критерии результата и ответственность; без неё незавершённое принимают за готовое | Слишком подробная карточка создаст лишнюю писанину | Внедрить короткий шаблон |
| I-05 | Контроль готовности выпуска | Отделяет готовые документы от готового APK; без него легко пропустить подпись или неверный репозиторий | Не превращать ручной список в обещание автоматической защиты | Внедрить |
| I-06 | Автоматическое архивирование памяти | Сдерживает рост документов; без него чтение со временем станет длиннее | Может спрятать важные факты; текущий объём ещё мал | Отложить |
| I-07 | Автоматический учёт времени задач | Поможет оценивать сроки; без него пока нет статистики | Измерение времени агента не равно полезной работе | Отложить до нескольких реальных задач |
| I-08 | Обязательные локальные Git-хуки | Запускают проверки перед коммитом; без них запуск остаётся ручным | Нужна установка на каждом компьютере, хук можно обойти | Отложить до стабильного набора проверок |
| I-09 | Автоматическое обновление upstream | Ускорит получение исправлений; без него нужно следить вручную | Конфликты, смешение релизов K-9/Thunderbird и beta | Отложить до собственного remote и сборки |
| I-10 | Отдельная панель показателей | Облегчит обзор большого проекта; без неё используются журналы | Новый сервис и дубли данных при нынешнем размере проекта | Отложить |

## Почему выбран этот способ

Вариант А: расширить только правила. Мало кода, но ошибки ссылок и окружения по-прежнему ищутся вручную.
Вариант Б: два небольших инструмента без новых зависимостей и три рабочих шаблона. Есть стоимость тестов, зато ошибки можно воспроизвести и обнаружить автоматически.
Выбран Б; не добавляется сервер, отдельная система задач или автоматическая публикация.

## Распределение проверки

| Агент | Область | Требуемое доказательство |
|---|---|---|
| Popper | I-01, проверка памяти | Успешный документ и намеренно испорченные примеры |
| Meitner | I-02, окружение | Тесты логики и реальный диагноз этого компьютера |
| Noether | I-03, матрица | Сверка с CI и сценарии docs / ошибка ссылки / Android |
| Lovelace | I-04, карточка | Примеры блокировки, нового документа и разделения работы |
| Fermat | I-05, выпуск | Проверка origin, отсутствующего APK и неуказанного сервера |

Автотесты подтверждают обнаружение конкретных ошибок. Проверка шаблонов подтверждает полноту разобранных сценариев, но не доказывает экономию времени в длительной работе. Проценты ускорения не измерялись и не заявляются.
Фактические результаты интеграции фиксируются в [work-log.md](work-log.md).

## Использование

1. Перед Android-сборкой запускать `scripts/project/Test-Environment.ps1`.
2. После изменения памяти запускать `scripts/project/Check-Memory.ps1`.
3. До правок выбрать проверки по [verification-matrix.md](verification-matrix.md).
4. Для содержательной задачи использовать [task-template.md](task-template.md) внутри журнала работ.
5. Перед публикацией заполнить [release-checklist.md](release-checklist.md) фактическими доказательствами.

Команды PowerShell и коды завершения сверены с [официальной документацией Microsoft](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_scripts?view=powershell-5.1).
