# Контроль готовности собственного Android-выпуска

Это допуск к выпуску, а не инструкция публикации. Порядок действий: [deployment.md](deployment.md).
Сравнение: копия deployment дублировала бы команды; обычные галочки не привязывают результат к сборке. Выбрана короткая таблица доказательств. Подробные тестовые сценарии остаются в [release testing checklist](../docs/release/testing-checklist.md), процесс upstream в [RELEASE.md](../docs/release/RELEASE.md) не является настройкой нашего выпуска.

## Карточка кандидата

- Дата / проверяющий: `<дата, ответственный>`.
- Исходники: `<commit SHA, ветка/тег, учтённые изменения рабочего дерева>`.
- Продукт: `<модуль, flavor, release variant, applicationId, versionName, versionCode>`.
- Артефакт: `<APK/AAB, путь или ссылка, SHA-256, ссылка на сборку этого SHA>`.
- Решение: `BLOCKED` до заполнения обязательных доказательств; `<ответственный, дата решения>`.

Каждая строка получает `PASS` только с доказательством для этого кандидата. Не выполнено, неизвестно, ошибка или пустое поле означают `BLOCKED`. `N/A` допустимо только с причиной для upgrade первого собственного выпуска и Docker без сервиса. `READY` требует PASS остальных строк и обоснованных N/A; это не означает, что публикация уже выполнена. Изменение исходников, варианта или артефакта требует повторной оценки затронутых доказательств.

| Контроль | Обязательные поля доказательств | Статус / ссылка на результат |
|---|---|---|
| Tests | По [testing.md](testing.md): точные команды, SHA, дата, exit code, отчёты lint/unit/прочих обязательных проверок; ручной smoke и регрессии; незапущенные проверки и причины | BLOCKED / `<отчёты>` |
| Branding / applicationId | По [branding.md](branding.md): утверждённые имя, иконка, поддержка, атрибуция; фактический applicationId из release-артефакта и соответствие собственному продукту | BLOCKED / `<решение, проверка артефакта>` |
| OAuth | Собственные регистрации каждого поддерживаемого провайдера, redirect URI и соответствие package/сертификату; вход и возврат в приложение при совместной установке с upstream | BLOCKED / `<провайдер, безопасная ссылка на регистрацию, протокол входа>` |
| Подпись и артефакт | Успешная release-сборка, SHA-256 файла, отчёт проверки подписи, публичный SHA-256 сертификата и соответствие ожидаемому; для магазина различать upload key и сертификат установленного APK | BLOCKED / `<отчёт, отпечаток, ответственный за ключ>` |
| Installation / upgrade | Устройство и Android/API, hash установленного APK (для AAB связь с доставленным APK), чистая установка; предыдущая собственная версия -> кандидат, совместимость подписи/applicationId, рост versionCode, сохранность аккаунтов и настроек | BLOCKED / `<протокол; для первого выпуска причина N/A только upgrade>` |
| Target repo | Утверждённые owner/repo, ветка/тег; фактические fetch и все push URL выбранного remote, цель release workflow; совпадение с репозиторием владельца, отсутствие upstream среди целей отправки | BLOCKED / `<решение, вывод read-only проверки>` |
| Rollout / rollback | Собственный канал, ответственный, начальная группа и критерии расширения/остановки; план остановки распространения и восстановления, доступный проверенный артефакт, совместимость данных и протокол репетиции | BLOCKED / `<план и репетиция>` |
| Docker, только при наличии сервиса | Ссылка на конкретный сервис и его цель в [deployment.md](deployment.md), версия/image digest, health check и проверенный rollback; без сервиса указать N/A и причину | `<PASS/BLOCKED/N/A, доказательство>` |

В доказательствах запрещены пароли, токены, приватные ключи, содержимое писем и персональные данные. Достаточны безопасные ссылки на отчёты, публичные идентификаторы и отпечатки. Наличие signing config не доказывает подпись артефакта; наличие OAuth-кода не доказывает собственную регистрацию.
Rollback должен учитывать уже обновлённые устройства: остановка rollout не возвращает установленную версию. Не считать установку старого APK поверх нового проверенным восстановлением; описать совместимый исправляющий выпуск и восстановление данных. Для первого выпуска также нужен план восстановления.

## Проверка ошибочных сценариев

Проверка правил по локальным фактам, без push, запуска workflow, установки APK или Docker.

| Вход | Ожидаемый результат | Результат проверки |
|---|---|---|
| Remote называется origin, но push URL указывает на upstream | Target repo BLOCKED независимо от имени remote и остальных PASS | Подтверждено текущим push URL; отправка не выполнялась |
| Docs checks успешны, но APK/AAB и Android-отчётов нет | Выпуск BLOCKED: docs PASS не закрывает tests, подпись и установку | Проверено сопоставлением правил с отсутствующими артефактами; успешные docs checks здесь условие сценария, не заявление об успешном Gradle |
| Требуют Docker без сервиса и цели | Docker-операция BLOCKED; для Android строка N/A с причиной, остальные блокировки сохраняются | Подтверждено отсутствием определённого сервиса в deployment; контейнеры не запускались |
