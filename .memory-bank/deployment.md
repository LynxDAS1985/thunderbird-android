# Репозиторий и выпуск

## Текущее состояние

`origin` указывает на официальный `https://github.com/thunderbird/thunderbird-android.git`.
URL репозитория владельца не предоставлен. Push наших изменений в официальный репозиторий не является публикацией собственного продукта.
Адрес сервера, роль сервиса, Docker-конфигурация и канал распространения не определены. Запрошены у владельца; данные других проектов не использовать.

Целевой вариант приложения — только Thunderbird `full`, см. [D-006](decisions.md). Для тестовой ручной установки использовать `distrib/thunderbird-full-debug.apk`; `foss` не готовить и не публиковать без нового решения владельца.

## Последовательность после снятия блокировок

Доказательства готовности каждого выпуска фиксировать в [release-checklist.md](release-checklist.md). Пустые поля и неизвестные результаты блокируют выпуск.

1. Настроить репозиторий владельца как `origin`, официальный источник сохранить как `upstream`; сначала проверить фактические remote.
2. Успешно завершить проверки из `testing.md`, проверить diff и состав коммита.
3. Создать коммит Conventional Commits и отправить текущую ветку в собственный репозиторий.
4. Собрать Android-артефакт варианта `full`; release подписать собственным ключом вне Git.
5. Проверить установку и обновление предыдущей собственной версии на устройстве.
6. Опубликовать APK/AAB в согласованном канале, записать версию, коммит, контрольную сумму и результат проверки загрузки.

## Сервер и Docker

Для установленного на телефоне приложения основной выпуск - подписанный APK/AAB. Docker может потребоваться для сборочного окружения, сайта загрузки или отдельного сервиса, но назначение ещё не выбрано.
До серверного развёртывания записать конкретные сервис, каталог, команду сборки, проверку работоспособности и способ возврата предыдущей версии. Затем обновить именно этот сервис и проверить доступность результата.
Не придумывать адрес, контейнер и команды выкладки. Перезапуск Docker сам по себе не обновляет приложение на телефоне.
